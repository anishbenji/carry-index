# Amendment to ADR-0018: inlined CSS and the hash-based CSP, spike numbers

- **Status:** Accepted (owner, spike gate, 2026-11-28)
- **Amends:** [ADR-0018](../0018-inline-css.md) (N3). Accepted at the spike gate, 2026-11-28; this amendment now applies to ADR-0018.
- **Source:** spike PR 7, `docs/spike/deploy-hydrated.md` on `spike/07-deploy-hydrated` at `4c2c820`; spike
  PR 8, `docs/spike/static-csp.md` on `spike/08-static-csp` at `b0f40c4`

## What the spike asked

Compare inlined CSS under a hash-based Content Security Policy with an external file. Report cold-load LCP for
each, and whether one hash holds for every page. Separately, the architecture doc's question 5: does a hash-based
CSP hold with Solid's inline hydration script?

## CSP: PR 8 (local)

- **Static build: one hash set covers every page, zero violations.** Each of the 14 pages carries one inline
  script (the shared snippet) and, with inlined CSS, one `<style>`, identical everywhere. `build-static.ts` hashes
  every inline script and style, fails the build unless all pages give the same set, and writes `_headers` from
  it. The header line is 398 characters.
- **Hydrated build: per-page hashes.** Three inline scripts are shared; the serialized page data differs on every
  page. The `/*` rule must hold the union (the 404 page cannot have its own rule): 16 hashes, a 1,155-character
  header line, plus one 53-character hash per page. Cloudflare documents a 2,000-character limit per header for
  Pages; PR 8 assumed the same for Workers Static Assets and did not check. The hydrated policy would stop fitting
  at about 30 pages. Per-path rules hit the 100-rule limit, and nonces need a Worker, which ADR-0046 rules out.
- **Test.** `e2e/csp.spec.ts` (Playwright, Chromium): policy checked on the listing, a bag page and the 404 page,
  every interactive part run, any violation fails. Result: zero violations, 6 of 6 pass (3 pages × 2 builds).

Policy (inline-CSS variant): `default-src 'self'; script-src 'self' 'sha256-<snippet>'; style-src 'self'
'sha256-<stylesheet>'; img-src 'self'; connect-src 'self'; font-src 'none'; object-src 'none'; base-uri 'none';
frame-ancestors 'none'; form-action 'none'; manifest-src 'none'; media-src 'none'; frame-src 'none';
worker-src 'none'`. No `'unsafe-inline'`.

## N3: PR 8 (local)

Measured at `b0f40c4`, same session, interleaved, median of 5, both under the hash CSP. Command:
`heavy-run.sh "ci-spike-static measure A/B" bash -c 'RUNS=1 bash scripts/measure-ab.sh smoke.json && RUNS=5 bash
scripts/measure-ab.sh measure-ab.json'`.

|---|---|---|---|---|
| Lighthouse LCP (simulated, cold) | 634 ms (625–670) | 791 ms (783–959) | 1,233 ms (1,217–1,251) | 1,222 ms (1,133–1,231) |
| FCP | 634 ms | 791 ms | 626 ms | 778 ms |

Inlining gives about 150 ms earlier first paint on both pages. LCP falls 157 ms on the text-led listing and does
not move on the image-led bag page. The cost is about 830 B brotli more HTML per page. The stylesheet is 866 B
brotli. Compression was measured locally only (`wrangler dev` serves `br` or `gzip`, never `zstd`); Cloudflare's
own compression was not measured. A warm second page was not measured.

## Proposed change

Accepted at the gate, 2026-11-28:

1. **Confirm ADR-0018.** Inline the stylesheet while it stays under about 10 KB compressed. Inlining adds one
   `style-src` hash, the same on every page, regenerated by the build.
2. **The CSP is generated at build time.** One hash set for the whole site, computed from the built pages and
   written into `_headers`. The build fails if any page needs a different set, and an end-to-end test fails on any
   violation. This rests on ADR-0015's proposed rule that page data never goes into an inline script.

Not verified: the 2,000-character limit for Workers Static Assets, the edge honouring `_headers` as
`wrangler dev` does, Firefox and WebKit.
