# packages/deploy contract tests

These tests encode privacy-wall design v2 (ADR-0049, accepted 2026-11-26) for the Saturday minimum, T1 to T9.
They were written before the implementation in `src/`, which now passes them, together with the tests each review
round added (listed below). T10 is real now (`t10-workflows.test.ts`, the workflow files); T11 to T13 are
`test.todo` in `later.test.ts` (Release 1.1, Kit minimum or edge only), and so are the parts of T9 that need code
that does not exist yet.

`packages/deploy/**`, `public-surface.json`, `never-public.ts` and these tests are never auto-merged.

## Running

```sh
bun run --filter @cj/deploy test                       # everything, T6 included
cd packages/deploy && npx vitest run test/t6-decoys.slow.test.ts   # T6 alone
```

T6 is slow (each case starts the real Wrangler, a few seconds each; 120 s timeout per case). It runs
`node_modules/.bin/wrangler` (4.168.0, checked by the test) with `deploy --dry-run`, which needs no network and no
Cloudflare account and uploads nothing. Run it again on every Wrangler upgrade. The tests run under Node through
Vitest (the import ban's TypeScript 7 parser does not work under Bun).

## Decisions these tests fix

- The CLI takes exactly `check <siteDir>`, `deploy <siteDir>` or `triggers <siteDir>` and deploys the site; the
  beacon's own gate is not specified here. `triggers` (`triggers.test.ts`, `sol-r5-first-deploy.test.ts`) runs
  `wrangler triggers deploy --config <sealed>/wrangler.json` once after the first deploy, on the same commit
  (workers.dev on, preview URLs off), because `versions deploy` applies no triggers. The first deploy runs with both
  public hostnames off; `triggers` refuses unless the active deployment is that build's tagged version alone at 100%
  (S5-5).
- Deploy commands (director decision after GPT-6.2 Sol security round 1): `wrangler versions upload --config
  <sealed>/wrangler.json`, then `wrangler versions deploy <id>@100% --config <sealed>/wrangler.json --yes` once that
  version checks clean; a recovery rollback is `wrangler rollback <previous-id> --config <sealed>/wrangler.json --yes`,
  never untargeted (it was `wrangler rollback --config <sealed>/wrangler.json --yes`).
- `confirmLive` (check 3's live check with a rollback callback) is kept for the T7 contract tests that specify it;
  the gate itself now runs `checkLive` and does its own targeted recovery (`cli.ts`).
- `MAX_FILE_BYTES` is 2 MiB.
- The beacon definition sets `find_additional_modules: false`: with `no_bundle`, Wrangler 4.168.0 otherwise
  attached a stray `.txt` file from the beacon's folder as a module (seen on 26 Nov 2026 while recording the
  fixture).
- Surface lines are `export.path: type`; problems are `{ path, rule }`, sorted by path.
- Private modules for the import ban: `@cj/schema/private`, `packages/schema/src/private`, `@cj/kit`,
  `@cj/worker-kit`, `apps/kit`, `workers/kit`.
